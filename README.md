# ApeRadar EX

ApeRadar EX 是《战舰世界》玩家战绩查看工具 ApeRadar 的社区增强分支。程序读取游戏生成的战斗信息文件，并通过公开 API 查询玩家数据；不会读取、修改或注入游戏进程。

> 本项目基于 zylalx1 的 ApeRadar 继续开发，EX 版本并非原项目官方发布版。

版本变化请查看 [更新记录](./CHANGELOG.md)。

## 下载

前往 [GitHub Releases](https://github.com/slowpoke0520/aperader_ex/releases/latest) 下载 `ApeRadar-win-x64.zip`，解压后运行 `ApeRadar.exe`。

运行环境：Windows x64。Release 提供 .NET 8 自包含程序，不需要另外安装 .NET Desktop Runtime。

首次运行后，打开“设置”，选择《战舰世界》安装目录。进入战斗时，程序会自动读取对局并显示双方玩家数据。

## 快速开始：记录并查看一艘船的对局表现

1. 解压后运行 `ApeRadar.exe`；在“设置”中选择正确的游戏安装目录。程序是 Windows x64 自包含版本，不需要安装 .NET。
2. 正常进行一场**随机战**。进入战斗后，雷达会保存本机舰船和双方开场阵容；战斗结束后会等待 Replay 写入完成，再导入结果。
3. 主窗口底部的“本次时段”摘要会自动显示当前连续游戏阶段的场次、胜率、场均伤害和 PR；点击摘要或“对局历史”进入个人提升中心。第一次打开或首次设置游戏目录后，程序会自动从旧到新扫描游戏 `replays` 目录中已有的录像。
4. 在顶部依次选择服务器、账号和舰船，例如选择“大和”。日期范围为空表示不限制日期；结束日期包含当天。
5. 选择要查看的曲线指标（胜率、伤害、击沉或 PR）以及滚动场数。默认“20”表示每个曲线点统计最近 20 场；选择“全部”则显示筛选结果的累计表现。

筛选后的汇总卡片和单场列表只会使用当前筛选到的记录。因此，选择“大和”后不会混入其他舰船的数据。关闭历史窗口不会停止后台的 Replay 监听；新完成的随机战会继续自动记录。

## 主要功能

- 显示账号和当前舰船的场次、胜率、经验、伤害等数据
- 使用 WoWS Numbers 公式计算账号 PR 和单船 PR
- 按标准 8 档 PR 色阶显示评分颜色
- 支持玩家关注状态、备注和再次遇到提醒
- 标记最近 5 局内遇到过的玩家
- 支持固定队友，避免重复遇到标记干扰
- 缓存玩家数据，并允许单独强制刷新某位玩家
- 支持多服务器和跨服对局
- 支持中英文界面及可配置的列表、图表和输出文本
- 自动记录本机玩家的随机战，并在“对局历史”中按服务器、账号、舰船和日期筛选
- 展示胜率、场均伤害、场均击沉和 PR 汇总，以及 10、20、50 场或全部场次的滚动曲线
- 自动监听并导入 Replay；Replay 暂不兼容时使用本机单船累计数据差值补查
- 自动按 45 分钟间隔划分游戏时段，并支持人工合并和分割
- 从 Replay 记录生存、生存时间、潜在伤害，以及可选的实验性承伤数据
- 支持收藏单局、添加复盘标签和自由备注
- 对比本次时段与本人同船历史，样本不足时不生成武断结论

## 对局历史与单船追踪

进入一场随机战后，ApeRadar EX 会保存当时的本机舰船和双方阵容快照，并监听游戏目录下的 `replays` 文件夹。首次启用时会从旧到新扫描已有的 `.wowsreplay` 文件；导入可在“对局历史”窗口暂停，下次启动会继续。

### 如何阅读历史窗口

- **本次时段**：显示最近一个连续游戏阶段的场次、胜率、场均伤害、平均 PR、生存率、潜在伤害和待补全数量。相邻两场随机战间隔不超过 45 分钟时自动归入同一时段。括号中的 `8/12` 表示 12 场中有 8 场拿到了该指标。
- **舰船趋势**：保留服务器、账号、舰船和日期筛选，可查看胜率、伤害、击沉、PR、生存率、潜在伤害和每分钟伤害曲线。默认滚动 20 场；实验开关开启后还可查看承受伤害和伤害交换比。
- **对局记录**：上方选择一场后，下方显示生存与潜在伤害、原始伤害分类、战前双方阵容，以及收藏、快捷复盘标签和自由备注。地图内部代号会转换为亚服官方名称；胜利为绿色、失败为红色。
- **时段历史**：上方选择一个时段，下方显示其全部对局。可多选相同账号和服务器的时段进行合并，也可选择某场对局并从该场之前分割；这些操作只调整分组，不修改或删除单场数据。
- **提升提示**：只比较同一舰船。本次时段至少 5 场且此前同船至少 20 场时，才显示当前值、历史基线、变化比例和双方样本数；否则只提示继续积累数据。提示表达相关变化，不把单一指标说成胜负原因。
- **底部 PR 数据版本**：PR 会根据当前 `expected_values.json` 重新计算。因此更新 PR 数据后，历史 PR 和曲线可能变化，这是期望值更新造成的正常变化，不代表旧对局被改写。

### 小样本如何显示

- 1～4 场：直接显示“胜 / 未胜 / 待确认”的实际场数，不用 `100%`、`0%` 这类容易误导的胜率评价。
- 5～19 场：可以查看短期波动，但界面会标为短样本；此时一次胜负仍会明显改变均值。
- 20 场及以上：标为较稳定样本，适合与同船个人历史基线对比，但仍不代表未来表现。
- 少于 3 个有效数据点时不绘制折线；3～9 个点会保留原始折线并显示高波动提示；达到 10 个点后正常展示所选滚动曲线。
- “有效数据点”只包含确实取得该指标的对局；Replay 或 API 没有提供的值保持为空，不会作为 0 参与统计。

### 按钮说明

- **刷新**：重新读取本地历史库并按当前筛选刷新窗口。
- **重新解析录像**：重新尝试此前解析失败或暂不支持的 Replay；适合游戏更新后安装了兼容版本时使用。
- **暂停导入**：暂停当前的首轮旧录像导入；下次启动会自动继续，不会丢失已导入数据。
- **重新补查**：立即重试等待中的 API 差值补查；适合网络恢复或解除战绩隐藏后使用。
- **打开数据目录**：打开 `%LocalAppData%\ApeRadar EX\History`，其中的 `history.db` 是本机历史数据库。
- **清空历史**：永久删除该数据库内的全部对局历史，程序会二次确认。此操作不影响关注名单和近期遭遇记录。
- **保存复盘**：保存收藏状态、快捷标签和备注到本地历史数据库；软件更新和更换安装目录不会删除。
- **合并/分割时段**：只改变对局的时段归属，不复制或删除 Replay 和历史记录。

数据来源按可信度区分：

- **Replay 精确**：录像中包含且能够确认属于本机玩家的战后数据。
- **Replay 推算**：由完整战斗事件推算的数据；当前解析器不支持时不会伪造这一状态。
- **API 精确**：战前、战后本机单船累计场次只增加 1，通过差值获得该场数据。
- **API 合并**：累计场次一次增加多场，只作为一个加权区间参与汇总，不伪装成多条单场记录。
- **仅元数据**：只保留时间、地图、舰船或阵容，结果仍未知。

网络离线时补查任务会留在本地数据库并在稍后重试。API 不能区分败北与和局时，结果显示为“未获胜”，不会错误写成“失败”。PR 在查看时按当前 `expected_values.json` 重新计算，窗口底部会显示 PR 数据版本。

### 伤害与击沉颜色如何计算

不同舰船的等级、定位和平均输出差异很大，因此历史中心不会用“达到固定伤害就显示某种颜色”的全局阈值。程序读取 `expected_values.json` 中该舰船的期望伤害和期望击沉，先按 WoWS Numbers PR 的伤害、击沉标准化方式分别计算，再把单项结果换算到同一套 PR 色阶。达到该船期望值时对应约 1150 的平均色档；高于或低于期望值时逐级变化。

这个颜色只表示“相对于该舰船期望值的本场表现”，不是完整 PR，也不代表单场胜负。完整 PR 还会计算胜负并按伤害、击沉和胜负加权。合并 API 区间会按区间场数计算期望总量，筛选汇总则对所含舰船的期望值加权，因此切换舰船或日期后颜色也会随样本重新计算。缺少该舰船期望值时仍显示原始数值，但不强行着色。

每一条记录都同时显示“数据来源”和“完整度”。可按下面方式判断是否需要处理：

- **Replay 精确 / Replay 推算，完整**：Replay 已提供可用结果、伤害和击沉，可以直接用于单场与曲线查看。
- **API 精确，完整**：Replay 不可用时，前后单船累计数据只增加一场，差值可靠，可直接使用。
- **API 合并，完整**：两次查询间新增了多场；总数据真实，但不会拆成虚假的多条单场记录，单场曲线不会把它当作一个普通单场点。
- **等待补全 / 部分**：录像可能提前结束或游戏刚结算，程序会继续等待或补查；可稍后点击“重新补查”。
- **版本不支持 / 解析失败**：通常是游戏补丁改变了录像格式。点击“重新解析录像”；若仍失败，保留录像并等待后续兼容更新，API 兜底不影响主雷达功能。

目前只追踪随机战。Replay 解析依赖游戏版本，游戏大版本更新后可能暂时回退到 API 补查；雷达和玩家标记功能不受影响。

### 高级 Replay 指标与实验开关

生存状态、生存时间、战斗持续时间和潜在伤害来自 Replay 事件。录像在本舰被击沉后提前退出时仍可记录“被击沉”和生存时间；录像在战斗结束前退出且没有本舰死亡事件时，生存状态保持未知，不会猜成“存活”。

“设置 → 高级 → 显示实验性 Replay 指标”默认关闭。开启后会额外显示承受伤害、伤害交换比和 Replay 中的原始伤害类型。原始类型编号与游戏版本有关，在没有可靠版本映射时软件不会强行标注为主炮、鱼雷或火灾。每个实验值都会明确标识；指标缺失时保存为空，不会作为 0 参与平均值。

## 三种更新的区别

设置页面提供三个互相独立的更新按钮：

- **检查软件更新**：从本仓库的 GitHub Releases 下载新版程序，校验 SHA-256 后由独立更新进程安装并重新启动。更新进度窗口会从下载开始显示百分比和已下载容量，并依次显示等待主程序退出、校验、解压、备份、安装、验证和启动；可随时点击“取消”，不需要通过任务管理器判断是否卡住。
- **更新船名列表**：更新 `Resources/Json/ships.json`，用于识别新版本加入或修改的舰船。
- **更新 PR 数据**：更新 `Resources/Json/expected_values.json`，用于计算 PR。

软件更新会保留 `WatchList.json`、玩家缓存、遭遇历史、窗口位置、日志和截图。船名列表与 PR 数据按版本选择：本机数据比安装包更新时保留本机文件，本机数据较旧或同版本时使用安装包文件。安装新版本前会备份将被替换的程序文件；安装或启动验证失败时，更新器会恢复原版本并尝试重新启动它。错误详情写入 `%LocalAppData%\ApeRadar EX\Update\UpdateError.log`。

> **从 2.1.1-ex.7 / 2.1.1-ex.8 升级的特别说明：** 这两个版本自带的旧更新器存在主程序未完全退出后仍继续覆盖文件的问题，因此它们无法靠自身可靠地安装首个修复版本。请先从 GitHub Releases 手动下载一次新的完整压缩包，退出所有 ApeRadar 窗口后解压覆盖；完成这一次升级后，后续版本即可使用带进度和回滚保护的软件内更新。

“设置 → 高级”中的**软件启动时自动检查更新**只控制软件版本检查：关闭后，启动不会访问 GitHub Release；“检查软件更新”按钮仍可随时手动使用。船名列表和 PR 数据仍由各自的手动更新按钮控制。高级页面的**查看更新日志**会打开全部 Release 的说明，便于在升级前了解功能变化和已修复问题。

## 数据文件

| 文件 | 用途 |
| --- | --- |
| `WatchList.json` | 关注状态和玩家备注 |
| `PlayerDataCache.json` | 玩家战绩缓存 |
| `PlayerIDCache.json` | 玩家名称与 ID 缓存 |
| `EncounterHistory.json` | 最近对局和固定队友记录 |
| `%LocalAppData%\ApeRadar EX\History\history.db` | 对局、时段、阵容、高级指标、复盘备注、Replay 状态、单船快照和待补查任务 |
| `Resources/Json/ships.json` | 舰船名称与基础信息 |
| `Resources/Json/expected_values.json` | PR 期望值数据 |
| `Resources/Json/release_data.json` | 发布包内置数据的版本、来源提交与 SHA-256 |

建议升级或迁移程序前备份 `WatchList.json`。

历史数据库不在软件安装目录内。软件更新、重新解压或更换安装目录不会删除它；所有历史数据仅保存在本机，程序不会上传这些记录。在“对局历史”中点击“打开数据目录”可以直接查看其位置。首次从旧版升级时会在同一目录生成 `history.db.pre-v2-时间.bak`，随后自动为旧对局建立时段。

## WG Public API application_id

Vortex 仍是默认数据源，一般无需配置。使用 WG Public API 时，可以在“设置 → 高级”填写自己的 `application_id`；留空则使用程序内置的兼容 ID。`application_id` 是 Wargaming 开发者应用的标识，不是账号密码，也不应填写 access token。

## 对局历史故障排查

- 没有新记录：确认设置中的游戏路径正确，并且对局模式是随机战。
- Replay 一直显示“不支持”或“失败”：游戏补丁可能改变了录像格式，可先使用“重新解析录像”；数据仍会尝试通过 API 补查。
- 一直显示“待补查”：检查网络和战绩是否公开，然后点击“重新补查”。网络错误不会删除任务。
- 数据库无法打开：程序会把确认损坏的数据库改名为 `history.db.corrupt-时间`，随后建立新库；可在数据目录中保留备份用于恢复。
- “API 合并”不是单场：这表示两次快照之间已经新增多场，程序只保留真实总差值，不猜测每一场的结果。
- 生存率或潜在伤害显示 `-`：该 Replay 可能过早结束、版本暂不支持，或当时没有产生对应统计事件；这不是 0。
- 看不到承受伤害和交换比：这些指标默认属于实验功能，请在“设置 → 高级”开启；关闭不会影响基础历史数据。
- 没有提升提示：同一舰船需要本次至少 5 场且此前至少 20 场有效记录，避免小样本误导。

## 从源码构建

需要安装 .NET 8 SDK：

```powershell
git clone https://github.com/slowpoke0520/aperader_ex.git
cd aperader_ex
dotnet restore .\ApeRadar_EX\ApeRadar_Src\ApeRadar.sln
dotnet build .\ApeRadar_EX\ApeRadar_Src\ApeRadar.sln -c Release
```

Release 构建产物位于：

```text
ApeRadar_EX/ApeRadar_Src/ApeRadar/bin/Release/net8.0-windows/win-x64/
```

## 发布 EX 版本

版本采用 `原版本-ex.增强版序号` 格式，例如 `2.1.1-ex.10`。生成 Windows x64 自包含发布包：

```powershell
.\Publish-Release.ps1 -Version 2.1.1-ex.10
```

提交后创建并推送相同版本的标签：

```powershell
git tag v2.1.1-ex.10
git push origin codex/personal-improvement-center
git push origin v2.1.1-ex.10
```

GitHub Actions 会自动构建并创建 Release。发布脚本会先运行测试，再分别生成主程序和单文件独立更新器。当前游戏版本的真实 Replay 端到端验证未通过时，不应推送正式版本标签。更完整的流程参见 [发布更新说明](./发布更新说明.md)。

每次运行发布脚本都会先执行 `Update-ReleaseData.ps1`：从 `wowsinfo/data` 选择版本号最高的正式服非 PT 标签生成中英文船名列表，并从 `wowsinfo/WoWs-Info-Seven` 的 `API` 分支固定最新 PR 文件提交。脚本会检查版本防回退、舰船数量、必需字段、可用 PR 条目和发布目录文件哈希；网络、格式或校验失败会终止发布，不会用旧数据继续打包。生成的 `ships.json`、`expected_values.json` 与 `release_data.json` 应随发布提交一起提交，确保源码与发布包可追溯。
